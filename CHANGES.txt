DivumWX - Boltek Lightning on NexStorm's native ngxarchive.json (for 2.0.0)
==========================================================================

Goes on top of version-2.0-beta at fc46106 ("earthquake-equal-earth.patch").
Applies with or without the repo-cleanup package.

This replaces divumwx-boltek-nexstorm-json.zip and
divumwx-boltek-direct-detector.zip (both parked; don't apply them).
NSDRealtime.txt is no longer read.

The file (worked out from a real one)
-------------------------------------
  TimestampEpoch  when written, Unix ms
  StrikeCount     NexStorm's running total     StormCount, StormData
  DetectorModel, SoftwareVersion, StationLat/Lon, AntennaAlignment
  StrikeData[]    one entry per strike:
    millis  strike time, Unix ms        time  same, seconds after local midnight
    dist    km                          bng   bearing, degrees true
    lat/lon strike position             (dist/bng match lat/lon to 1 km / 0.1 deg)
    type 1 = cloud-to-ground (assumed), polarity 1 = +, 0 = - (assumed)
    compoundType, correlated, NMEAChecksum: not identified, not used

What changed
------------
- bin/user/divumwx_boltek.py 1.1.0 (rewritten around ngxarchive.json):
  * [BoltekLightning] ngxarchive_file = ngxarchive.json (relative to the
    DivumWX site folder, or absolute); close_distance = 16 (km).
  * Each listed strike is counted once, at its own time. One that belongs
    to an interval already saved (read just after the interval closed,
    listed while WeeWX was stopped, or already in the file on the first
    run) is added to that interval's record, so the hourly chart/records
    show it when it happened. No more "earlier today" 00:00 record.
  * StrikeCount rising by more than the new listed strikes: the extra is
    counted too, at the time it's seen ("undated"). boltek.json shows how
    many of each were counted since start (realtime.counted_listed /
    counted_undated) so we can see after a storm whether StrikeData lists
    every strike.
  * Worked out from the strikes: strikes/min (last 60 s), average distance
    over the last hour, approaching/receding (last 15 min vs the 15
    before), today's peak rate. CG count = type 1; close = within
    close_distance.
  * boltek.json also carries the latest 100 strikes [time, km, bearing,
    lat, lon, type] (realtime.recent_strikes), ready for a strike map.
  * A half-written file (NexStorm mid-rewrite) is skipped and retried.
  * Database layout unchanged, so existing divumwx_boltek.sdb files carry on.
- install.py: adds ngxarchive_file and close_distance (set-once, with
  comments); removes 1.0.0's realtime_file / distance_unit when they still
  have their defaults; message updated.
- cardBoltekLightning.js 1.1.0 (in cardsBundleNew.js): comments/tooltip
  only; Bearing works from the strike data. ?v= is dd758a5d in
  index.html, hyperIndex.html and lexendIndex.html.
- modalBoltekLightning.html 1.1.0: live strip adds Bearing + distance,
  Storms, Detector (with NexStorm version); Last Strike shows the time
  even without a type.
- CHANGELOG.md (Boltek section rewritten for ngxarchive.json) and
  INSTALLATION_GUIDE.md.

Tested with your real ngxarchive.json: parsing; first-run back-fill into
the right hours (09:00 1, 10:00 2, 11:00 3); new strikes counted once;
StrikeCount top-up; strike read after its interval closed; restart with
strikes listed while stopped; NexStorm restart; half-written file; stale
and missing file; approaching/receding; installer merge (new, upgrade,
customised). The UPDATE path also run through WeeWX's real database
manager. Card and chart page rendered in Chromium from the service's own
output.

REMINDER: the repo root still has CHANGES.txt, DELETED-FILES.txt,
